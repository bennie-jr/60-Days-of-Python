### DAY 60: Build and Publish a Python Package

Today marks the end of this 60 Days with Python journey. I built the last app, app 18 and this is a python package. This app helped me learn how to create and distribute your own Python packages through PyPi (Python Package Index) so everyone can install your package using "pip." 

Recap on what I did yesterday. I started with content-based filtering by working with term frequency and inverse frequency. I created a function which took movie title and number of similar movies and returned the most similar movies based on those parameters. Once I was done with content-based filtering, I moved on to work on collaborative filtering with machine learning. I had to go through stages like creating the dataset and building the trainset. After building the trainset, I went ahead to train the model and then validate the model.

Today, I built app 18 which is a python package. With this app I created and distributed my own python package through Python Package Index. I started by reusing the code from day 4 which was the invoice generator app and this is what I created the package out of. I converted the code to fit into a function because modules or packages require a function or a class. After I was done refactoring the code, I tested the soon to be published package and I didnt see any problems. I created a specific folder for the package and put the python file which had the code in there. I also add an ""__ init __.py"" to help identify that it is a package even tho from python 3.3 it wasn't necessary anymore. I created a setup.py file which contained all the info the package would need for publication and distribution. I used the sdist command with setup.py to create the package distribution zip file and then when I was done I used twine to publish/upload the package to PyPi.
